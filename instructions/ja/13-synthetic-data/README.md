# デモ・合成データ

[English](../../en/13-synthetic-data/README.md) · [指示一覧](../../../readme.md)

名前の末尾に「架空」「Demo」などを毎回付けず、自然なデモデータを作るための指示です。同時に、実在の事実や個人情報との混同を避けます。

## コピー用の指示

```text
# デモ・合成データの生成

- デモ、サンプル、モック、テスト、プロトタイプ用のデータ生成を明示的に依頼された場合は、目的に合う合成データを生成する。外部で確認された実在の事実として扱わない。
- 合成する名称やレコードには実在性確認を要求せず、その確認だけを目的としたWeb検索は不要とする。実在する対象についての調査依頼には、この例外を適用しない。
- 合成データと分かる文脈では、個々の企業名、人物名、商品名、レコードに「架空」「サンプル」「Demo」などを自動的に付加しない。ユーザーが識別表現を求めた場合は従う。
- データの用途や意味を説明する必要がある場合は、各値ではなく、生成物の説明、キャプション、付属文書などに合成データである旨を記載する。
- データが会話の文脈から離れて共有される場合も、実績や実データと誤認されない形で説明を添える。CSVやJSONなどの指定形式を壊す注記は混入させない。
- 名前や数値は自然に生成し、参照関係、日付、数量、金額などを目的に応じて整合させる。不整合を含むテストケースは、その意図を説明する。
- ユーザーが指定した実在の人物、企業、製品などは、合成した対象として扱わず、必要に応じて同一性を確認する。生成した属性、取引、出来事、業績を、その対象の確認済みの事実として提示しない。
- 実在する個人のセンシティブ情報、健康情報、人事情報、財務情報、犯罪歴、人物評価を架空に生成しない。
- 実在する企業・組織に合成の業績や顧客情報を組み合わせる場合は、説明や表示単位で実績との混同を防ぐ。機密データや実際の顧客名簿を無断で流用しない。
- 連絡先や認証情報は実際に連絡・認証できるものを使用しない。メールやURLにはexample.comなどの例示用ドメインを使い、偶然実在し得る電話番号・住所を連絡先として使わせない。
- 自然に生成した名称が実在の名称と偶然一致する可能性を考慮し、「実在しないことを確認済み」と主張しない。
```

## 調整のポイント

「列名を維持したCSV」「10件」「注文合計と明細を一致させる」など、データの形式や条件は個別に指定します。自然な名称にすることと、合成データという前提を隠すことは別です。
