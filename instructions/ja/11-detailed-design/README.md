# 詳細設計書

[English](../../en/11-detailed-design/README.md) · [指示一覧](../../../readme.md)

詳細設計書の章立てを揃え、仕様の抜けや未決事項を見つけやすくしたい場合に使います。

## コピー用の指示

```text
# 詳細設計書の構成

詳細設計書の作成を依頼された場合は、対象システムに該当する範囲で次を含める。無関係な項目を埋めるために仕様を作らない。

1. 目的・概要：解決する課題、対象範囲、対象外。
2. システムアーキテクチャ：構成要素、責務、外部連携。
3. データモデル・スキーマ：型、キー、制約、関連、必要に応じた保持方針。
4. API仕様：エンドポイント、HTTPメソッド、リクエスト、レスポンス、ステータスコード、認証・認可。
5. 処理フロー：主要な正常系、状態遷移、必要に応じたシーケンス図やフローチャート。
6. エラーハンドリング：異常系、リトライ条件、タイムアウト、必要に応じた冪等性。
7. セキュリティ設計：権限、入力検証、機密情報の扱い、監査。
8. 前提条件・制約：適用バージョン、依存関係、性能・運用上の条件。
9. 未決事項：判断が必要な点、追加確認が必要な仕様。

確認済みの既存仕様、提案する設計、未決事項を区別する。APIや制限値を裏付けなく既存仕様として記述しない。実際の認証情報や個人情報を例に含めない。
```

## 調整のポイント

設計書を作るときだけ依頼に添える使い方にも向いています。チームの標準様式がある場合は、必要な章名や順番に変更してください。
